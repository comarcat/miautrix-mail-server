# v2.1 Protocol Compliance Audit (read-only)

**Audit baseline:** branch `release/v2.1`, v2.0.0 release handoff; source inspection only. IMAP is explicitly excluded because a parallel worker owns it. No production/public probes were made. Findings describe repository code and registered surfaces, not deployed reachability. File/line references are repository-relative. “Not advertised” means the listener does not put it in its EHLO response; no inference of support is made from helper names alone.

## Executive summary

The native public surfaces are SMTP inbound on 25, SMTP submission on 587 and implicit-TLS submission on 465, plus IMAP on 993 (out of scope). The Sieve project is a partial script validator/storage helper and has no ManageSieve listener or demonstrated delivery-time interpreter. JMAP's project contains only a `.csproj`, with no registered endpoint. HTTP calendar, contacts, and Sieve-rule APIs are application-specific JSON APIs, not CalDAV/CardDAV, iCalendar scheduling, or ManageSieve. Autoconfig/autodiscover and MTA-STS/TLS-RPT endpoints are not found in the Web host routes. Outbound mail is only dispatched through the Cloudflare API transport; no SMTP client/MX delivery path is present in the Worker.

The SMTP implementation is deliberately small. Its EHLO response advertises only STARTTLS (587 pre-TLS), AUTH LOGIN/PLAIN (after TLS), and SIZE 26214400. The advertised SIZE behavior is not enforced in the listener and multiple fundamental RFC 5321 behaviors are incomplete. The advertised extensions therefore need to be implemented or removed before release; any extension removal must be reflected in clients/configuration and validation.

## 2. Compliance matrices

### 2.1 SMTP inbound MTA (RFC 5321, port 25)

The port-25 session uses `StreamReader.ReadLineAsync`, a one-recipient envelope, a string builder for DATA, and common command handling (`SmtpListenerService.cs:138-175,317-411`). The command parser is prefix-based (`StartsWith`) and does not validate complete SMTP grammar. EHLO output is at `SmtpListenerService.cs:179-193`.

## 3. Gaps ranked by severity

Severity counts below are actionable audit rows, grouped by work area, excluding N/A rows and duplicates where the same root defect appears in multiple matrices. **Critical: 2; High: 31; Medium: 16; Low: 8.** Counts are approximate because one shared implementation defect can appear in multiple protocol rows; the top ten below consolidates roots.

### Critical

1. Unbounded SMTP command/DATA lines and message accumulation permit memory exhaustion (`SmtpListenerService.cs:174-175,374-386`).
2. Advertised `SIZE 26214400` is not enforced; same unbounded DATA exposure (`SmtpListenerService.cs:191,374-386`).

### High

1. SMTP inbound port 25 rejects STARTTLS despite mode/docs saying opportunistic, exposing downgrade/no-TLS transport and breaking RFC 3207 clients (`SmtpListenerService.cs:22-23,197-203`).
2. RFC 5321 MAIL/RCPT state and recipient set are incomplete; accepts out-of-order state and overwrites all but last recipient (`SmtpListenerService.cs:317-361`).
3. DATA framing lacks enforced size/timeout/EOF safeguards; queue acceptance after truncated connection is not proven (`SmtpListenerService.cs:363-411`).
4. VRFY and EXPN return unrecognized-command 500 rather than privacy-safe 252; HELP is also missing (`SmtpListenerService.cs:430-438`).
5. SIZE is advertised without support for MAIL SIZE semantics or actual byte enforcement (`SmtpListenerService.cs:191,317-331,374-386`).
6. Inbound SMTP does not apply demonstrated SPF/DKIM verification/DMARC evaluation; a DKIM helper alone does not establish verification (`Protocols.Smtp/DkimService.cs:9-14,63-110`; `SmtpInboundHandler.cs`).
7. No RFC 3464 DSN/bounce generator for permanent/expired delivery failures (`OutboundQueueDispatcher.cs:219-231`).
8. Outbound direct-MX SMTP is absent; Cloudflare HTTP API is the only registered transport, so MX fallback and opportunistic SMTP TLS do not occur (`Worker/Program.cs:129-140,173`; `OutboundQueueDispatcher.cs:132-232`).
9. Outbound DKIM signing helper is not wired into dispatch; queued raw message goes directly to transport (`DkimService.cs:40-60`; `OutboundQueueDispatcher.cs:219-225`).
10. Sieve tokens are allowlisted without full grammar or execution, and active scripts are only stored (`SieveParser.cs:10-20,23-115,118-187`).

Other high gaps: no JMAP runtime despite design claims; no CalDAV/CardDAV if advertised as standards; no delivery-time Sieve; unsupported Sieve extension semantics; no documented test evidence for RFC 6409 §8 header transformation; absent explicit TLS version floor; inbound command replies/state handling incomplete; unsupported DNS policy evaluation for direct outbound.

### Medium

Enhanced status code consistency; HELO-specific behavior; dot transparency coverage; STARTTLS state reset coverage; SMTPUTF8 not implemented; SMTP 8BITMIME not implemented; ManageSieve absent despite architecture listing it; MTA-STS/DANE/TLS-RPT policy absent; iCalendar/iTIP interoperability is unproven; TLS 1.2+ floor/cipher policy is implicit; SMTP auth parser needs strict SASL grammar; queue retry lifetime needs proof against RFC 5321; WebDAV is absent (not a defect absent a claim); cert lifecycle/observability needs hardening.

### Low

CHUNKING/BINARYMIME, DSN ESMTP parameters, XOAUTH2/SCRAM, autoconfig/autodiscover, RFC 6186 DNS publication, ManageSieve as optional product feature, POP3S listed as optional architecture feature, and non-advertised extensions not implemented. Low means not currently advertised or promised in runtime; do not mark as implemented.

## 5. Explicit non-goals and risks

### Non-goals for this audit

- IMAP and IMAP4rev2 (parallel workstream).
- Production access, public DNS/HTTP probes, live SMTP delivery, or external client testing.
- Editing source, tests, scripts, migrations, DNS, or deployment configuration.
- Certifying deployment firewall/Cloudflare configuration, DNS records, current certificate chain, or live port availability.
- Implementing every optional SMTP extension. Only advertised or expressly promised features must be completed; no capability should be advertised ahead of its tests.

### Risks and limitations

- This is static source review. Test evidence names suites found in the repository, but the full test suite was not executed in this worker session; test DB safety/configuration was not independently confirmed.
- RFC conformance is larger than handler presence. Prefix parsing, helper methods, or product models are not proof of interoperable behavior.
- Application code cannot establish public DNS, Cloudflare edge routing, certificate deployment, or externally reachable ports.
- The project architecture and historical release documents describe future/optional services (JMAP, ManageSieve, POP3S); those statements should not be copied into current capability claims without runtime evidence.
- Applying SPF/DMARC or Sieve rejection late in the pipeline risks backscatter and duplicate delivery; policy and queue stages need explicit design before implementation.
- Adding multi-recipient support, exact octet preservation, or new per-domain verification state can affect queue/schema contracts. Migration needs are marked provisional pending package design.
- JMAP, CalDAV/CardDAV, and complete Sieve are substantial standards implementations; partial endpoints marketed under those names create interoperability and security expectations they do not meet.

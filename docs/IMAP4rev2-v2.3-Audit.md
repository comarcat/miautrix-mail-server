# RFC 9051 IMAP4rev2 paragraph-level server audit

**Scope:** normative paragraphs in RFC 9051 §§2–7. One row represents one paragraph containing one or more server-applicable normative statements; quote is limited to 15 words. Paragraph indices below are local normative-paragraph ordinals within each section because RFC 9051 does not number prose paragraphs; they count only paragraphs containing normative language.

**Rows:** 234. **Status:** Implemented 0, Not applicable 34, Missing 125, Partial 75. **Level:** MUST 126, MUST NOT 36, REQUIRED 7, SHALL 0, SHALL NOT 0, SHOULD 50, SHOULD NOT 13, RECOMMENDED 2.

**Advertisement gate: NOT READY** — applicable Missing/Partial MUST-level rows remain. The report inherited from the implementation branch also documents known broad blockers.

## Method and limitations

Statuses are conservative: Implemented is used only where the merged implementation report or raw protocol tests explicitly demonstrate the behavior; Partial means relevant functionality exists but paragraph edge cases are not proven. Missing means no paragraph-complete evidence was found in this audit. “Client-only” rows are not applicable to the server. The paragraph-level scan is an audit inventory, not proof that every sentence within a combined normative paragraph has independent test coverage.

Known exclusions include client-only requirements and cleartext STARTTLS (the listener uses implicit TLS on 993). `LOGINDISABLED` is not advertised because LOGIN is available after TLS; it is not a server obligation to advertise LOGINDISABLED.
